# v2.2 validation record

Target version: 2.2.1. Validation date: 2026-08-09. This record covers the 2.2
series: 2.2.0 (weekly brightness schedule) and 2.2.1 (schedule editor
completion and Go formatting).

## Host validation

| Check | Result |
|---|---|
| `gofmt`, `go vet` (host and linux/arm64) | PASS |
| Unit tests, all packages | PASS |
| Qt `qmllint` with AppLoad stubs | PASS via tagged CI |
| Qt resource compile, ARM64 cross-build, bundle self-check | PASS |
| Linux race tests, ShellCheck, `govulncheck`, CodeQL | PASS via tagged CI |

The 2.2.0 tag was never released. Its host checks failed on `gofmt`; 2.2.1
normalizes the backend message constants and restores a clean run.

New coverage in this release: the weekly brightness schedule is persisted
through the existing configuration round-trip tests, and the half-hour boundary
arithmetic reuses the quiet-hours window helpers already covered by unit tests.

## Device validation

**Not re-exercised for this release.** The 2.2 series was validated on the host
and in CI only. The device baseline remains the v2.1 record: reMarkable Paper
Pro (`reMarkable Ferrari`), aarch64, reMarkable OS 3.27.3.0, kernel
`6.12.49+git-imx8mm-ferrari-g68b95e858a0a`.

The weekly brightness schedule added in 2.2.0 drives the front-light path that
v2.1 validated on hardware, but the schedule editor, the half-hour boundary
application, and the system-brightness-mode switch have not themselves been
confirmed on a device. Anyone installing 2.2.1 should treat those three
behaviours as untested on hardware.

## Known limitations

Carried forward unchanged from the v2.1 record:

- reMarkable OS 3.26.x remains installer-allowed but has not been exercised on
  hardware. Only 3.27.3.0 has.
- A multi-day battery runtime figure cannot be produced during a release; the
  in-app battery test is the supported way for an owner to measure their own.
- The colour palette used for dithering is an approximation of the panel's
  displayable set. It is overridable via `dither_palette` in `config.json` for
  anyone who measures a better one.
- The tablet cannot update itself. The update check only reports that a newer
  release exists; installing it still needs the Windows installer.

New in this release:

- Enabling the weekly schedule turns off reMarkable system-brightness mode. A
  user who later disables the schedule does not get system-brightness mode back
  automatically; they set it again themselves.
