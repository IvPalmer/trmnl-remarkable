# v2.4 validation record

Target version: 2.4.0. Validation date: 2026-08-12. This record covers the 2.4
series, which is a bug-fix release for on-screen keyboard dismissal in Settings
([#9](https://github.com/usetrmnl/trmnl-remarkable/issues/9)). Nothing in the
backend, the installer, or the payload changed, so the 2.3 record still stands
for everything except the app UI.

## Host validation

| Check | Result |
|---|---|
| Qt `qmllint` with AppLoad stubs | PASS |
| App loads with no QML runtime or binding errors | PASS |
| Keyboard state tracks field focus, and clearing focus resets it | PASS |
| **Hide keyboard** does not overlap the header title or the close button | PASS, rendered at 1620 × 2160 |
| `gofmt`, `go vet`, unit tests, cross-builds | PASS, unchanged from 2.3 |

The UI checks were run against desktop Qt 6.8.3 with the AppLoad stub, driving
the Settings page directly: focusing the API key field raises the keyboard
state, `dismissKeyboard()` clears it, and Settings stays open.

## Device validation

**The fix has not been exercised against the reMarkable on-screen keyboard on
hardware.** The desktop harness confirms the app-side half — focus moves off the
field and the app asks the input method to hide — but whether the tablet's
keyboard panel closes in response can only be confirmed on the device. The
device baseline is unchanged from v2.1: reMarkable Paper Pro (`reMarkable
Ferrari`), aarch64, reMarkable OS 3.27.3.0.

## Known limitations

Carried forward from v2.3, except as noted:

- reMarkable 1 and reMarkable 2 remain unvalidated on hardware.
- reMarkable OS 3.26.x remains installer-allowed but has not been exercised on
  hardware. Only 3.27.3.0 has.
- The README's nine-day figure is a Paper Pro measurement with the front light
  off, not a per-device specification. The in-app battery test remains the
  supported way for an owner to measure their own.
- The colour palette used for dithering is an approximation of the panel's
  displayable set. It is overridable via `dither_palette` in `config.json`.
- The tablet cannot update itself. The update check only reports that a newer
  release exists; installing it still needs the Windows installer.
- Disabling the weekly brightness schedule does not restore system-brightness
  mode automatically.

New in this release:

- A text field near the bottom of Settings can still sit behind the keyboard
  while it is open. The page scrolls, and the dismiss button is pinned to the
  top and clear of the keyboard, so the field stays reachable; the page does not
  scroll itself to keep the focused field in view.
